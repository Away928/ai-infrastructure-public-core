# 经历证据与量化：从 resume-quantifier 提炼

## 证据等级（从强到弱）
1. **原始可核验记录**：公开论文、成绩、获准披露的项目产物、工作日志及原始统计；核对主体、日期、口径和单位。
2. **项目资料支持、待核准公开**：内部材料或个人工作记录只能作为私下核验依据，未经授权不得照搬公开。
3. **用户陈述、待核实**：可提问澄清；不得直接当成已验证成就。
4. **建议或推断**：只作为候选问题，绝不转化为事实或数字。

## 从模糊经历发现可验证指标
- 投资/研究：覆盖的标的、完成的模型/报告、数据清洗规模、研究问题与可证明的个人贡献；不要将策略预测自动说成实盘收益。
- AI/软件：本人实现了什么模块、样本/语料规模、可复现的测试指标、运行环境及基线；区分原型/离线测试/生产部署。
- 咨询/业务：分析行业、项目周期、客户交付物（仅在允许披露时）、独立负责部分；团队合同额与本人创造收入不得混为一谈。
- 学术/RA：论文角色、项目导师、是否投稿/录用/发表，以及是否独立完成方法；不得从合作署名推断第一作者。
- 提问模板：做了什么？您自己做了哪一步？何时？原始记录在哪？定义/分母是什么？能否对外披露？

## 计算与表达
- 有底层记录才能计算：增长率=(新值-旧值)/旧值，先确定方向、时间范围和零分母情形；说明是百分比还是百分点。
- 对无法核实的数字，使用**不含数字但准确的具体任务、方法与结果**，不要凭印象做“保守估计”、臆造范围或将团队指标归为个人。
- 可以建议测量项目数、周期、样本量、错误数、耗时等，但在完成核验前都用“待核实”，不要默认每条 bullet 必须有数字。
- 输出：原始主张｜证据/出处｜事实等级｜保密/披露限制｜建议表述｜需要用户确认的问题。
